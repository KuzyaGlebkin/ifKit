## ADDED Requirements

### Requirement: Глобальный учёт seen для статического слоя before/after
Движок SHALL хранить отдельный список хешей (`staticSeen`) для блоков, относящихся только к контенту зон static `before` и `after` при сборке `#scene-content`. Эти блоки SHALL NOT использовать ключ текущей сцены для решения о классе `paragraph--unseen`. Список SHALL сохраняться и загружаться вместе с per-scene картой согласно формату ключа `ifkit:seen`.

#### Scenario: Один статический текст обновился в одной сцене, переход без повторной подсветки
- **WHEN** автор задал общий блок в static `before` (например строка состояния), игрок изменил связанное с ним состояние в сцене A и увидел подсветку этого блока, затем перешёл в сцену B без изменения того же блока между рендерами
- **THEN** указанный статический блок в сцене B не получает класс `paragraph--unseen` при том же HTML, как на момент окончания рендера сцены A

#### Scenario: Статический блок реально изменился — подсветка снова появляется
- **WHEN** между двумя рендерами (неважно, на какой сцене) изменился HTML одного из дочерних блоков статического слоя
- **THEN** только изменившиеся статические блоки получают класс `paragraph--unseen`

### Requirement: initSeenContent загружает хранилище из localStorage
Функция `initSeenContent()` SHALL читать ключ `ifkit:seen` из `localStorage`. Поддерживаемый контракт: объект с полем `scenes`, значение которого — объект, содержащий только ключи строк и значения массивов строк (хеши виденных блоков на сцену); опциональное поле `staticSeen` — массив строк (глобальный статический слой); при отсутствии `staticSeen` трактовать как пустой массив. Во всех остальных случаях (`localStorage` пуст или ключ отсутствует, парсинг JSON не удался, корень не объект, другая структура, включая устаревший плоский `Record<string, string[]>` без вложения в `scenes`) SHALL установить внутренние `scenes` и `staticSeen` пустыми без выброса исключения в игровой код. Специальная миграция устаревших форматов не требуется; при желании игрок сбрасывает просмотренное уже существующим действием в настройках.

#### Scenario: Первый запуск — хранилище пустое
- **WHEN** в `localStorage` нет ключа `ifkit:seen`
- **THEN** `initSeenContent()` завершается без ошибки, внутреннее состояние — пустые `scenes` и пустой `staticSeen`

#### Scenario: Неподдерживаемый формат — чистое состояние без ошибки
- **WHEN** значение по ключу есть, но является устаревшим плоским объектом вида `{"room":["abc123"]}` без поля `scenes`
- **THEN** после `initSeenContent()` внутренние `scenes` и `staticSeen` пусты и запуск не прерывается

#### Scenario: Валидный новый формат — staticSeen и сцены восстанавливаются
- **WHEN** значение есть валидный JSON `{"scenes":{"room":["a"]},"staticSeen":["s1"]}`
- **THEN** после `initSeenContent()` оба набора восстановлены, хеш статического слоя `"s1"` не подсвечивается повторно при неизменном HTML блока статики

### Requirement: markAndHighlight помечает новые блоки и сохраняет в localStorage
Функция `markAndHighlight(element: HTMLElement, sceneKey: string, enabled: boolean)` SHALL:

1. Если `enabled === false` — не добавлять классов и завершиться
2. Если прямой дочерний элемент `element` помечен как регион тела сцены для учёта seen (контракт с `compose` / static-scene-zones), для каждого **его** прямого дочернего элемента: вычислить хеш `innerHTML`, сравнивать и записывать в хранилище по ключу текущей сцены как ранее для per-scene контента (добавлять класс `paragraph--unseen` при отсутствии хеша в множестве этой сцены)
3. Если прямой дочерний элемент помечен как регион статического слоя before/after для учёта seen, для каждого **его** прямого дочернего элемента применять то же правило подсветки, но использовать глобальный список `staticSeen`
4. Если у прямого дочернего элемента нет маркировки региона (режим без зон-static или только контент сцены), сохранять прежнее поведение: обрабатывать каждого прямого ребёнка `element` как per-scene по `sceneKey`
5. После обработки сохранить обновлённые `scenes` и `staticSeen` в `localStorage`

#### Scenario: Первый рендер сцены — все блоки тела подсвечены
- **WHEN** `markAndHighlight` вызван для сцены, которая не встречалась ранее в per-scene хранилище
- **THEN** каждый обрабатываемый блок тела сцены получает класс `paragraph--unseen`

#### Scenario: Повторный рендер того же контента сцены — нет подсветки для тела
- **WHEN** `markAndHighlight` дважды с одинаковым HTML контента регионов «тело сцены» для этого `sceneKey`
- **THEN** при втором вызове ни один из элементов этих регионов не получает класс `paragraph--unseen`

#### Scenario: Один блок в теле изменился — подсвечен только он
- **WHEN** первый рендер: два блока в регионе «тело сцены»; второй рендер: изменился второй блок
- **THEN** только изменившийся блок получает класс `paragraph--unseen`

#### Scenario: enabled === false — классы не добавляются
- **WHEN** `markAndHighlight(el, sceneKey, false)` вызван
- **THEN** ни один элемент не получает класс `paragraph--unseen`

#### Scenario: Хранилище сохраняется в localStorage после маркировки
- **WHEN** появились новые блоки и в статике и в теле одного рендера
- **THEN** ключ `ifkit:seen` отражает обновление и поля `staticSeen`, и нужного `sceneKey` внутри `scenes`

### Requirement: resetSeenContent очищает хранилище
Функция `resetSeenContent()` SHALL удалять ключ `ifkit:seen` из `localStorage` и сбрасывать внутреннее состояние модуля, включая и per-scene карту, и `staticSeen`. После вызова следующий `markAndHighlight` обрабатывает все блоки как новые.

#### Scenario: После сброса блоки снова подсвечиваются
- **WHEN** блоки были виданы, затем вызван `resetSeenContent()`, затем снова `markAndHighlight`
- **THEN** все обрабатываемые блоки получают класс `paragraph--unseen` согласно правилам регионов

### Requirement: Сброс просмотренного контента только по явному действию в настройках

Движок SHALL NOT вызывать `resetSeenContent()` при старте новой игры из стартового меню сессии (кнопка «Новая игра» / эквивалент). Полный сброс хранилища `ifkit:seen` SHALL выполняться только по пользовательскому действию в модалке настроек, которое специфицировано в `settings-modal` (кнопка сброса истории прочтения, вызывающая `resetSeenContent()`).

#### Scenario: Новая игра не очищает ifkit:seen

- **WHEN** в `localStorage` есть ключ `ifkit:seen` с непустыми данными и пользователь активирует «Новая игра» в стартовом меню
- **THEN** после запуска первой сцены ключ `ifkit:seen` по-прежнему существует и его содержимое для целей учёта seen не очищено этим действием

#### Scenario: Сброс через настройки по-прежнему очищает seen

- **WHEN** пользователь нажимает кнопку сброса истории прочтения в модалке настроек
- **THEN** вызывается `resetSeenContent()` и хранилище seen очищается согласно существующему требованию «resetSeenContent очищает хранилище»

## Context

В коде и спеках есть флаг `quietMusicForScreenReader`: он умножает только музыкальный мастер-гейн на константу α (`SCREEN_READER_MUSIC_ATTENUATION` в `audio.ts`), отдельный чекбокс в модалке между строками «Музыка» и «Звуки». Тип `Settings`, `user-settings`, `audio-engine`, `settings-modal` и `i18n` завязаны на это поле.

## Goals / Non-Goals

**Goals:**

- Убрать настройку «Тихая музыка» из продукта и контракта настроек.
- Ввести «Громкость» как общий множитель для музыки и звуков с тем же UX-паттерном, что у строк «Музыка» и «Звуки»: подпись → чекбокс «ветка включена» → ползунок 0–1 с шагом 0.1 → проценты и локализуемый `aria-valuetext`.
- Разместить блок общей громкости в модалке между рядом «Акцент» и строкой «Музыка».

**Non-Goals:**

- Менять поведение crossfade, кэша буферов или intent-музыки кроме формул gain.
- Добавлять отдельные пресеты или автоматику под скринридер взамен удалённого флага.

## Decisions

### 1. Имена полей в `Settings`

**Выбор:** `masterVolume: number` (0–1) и `masterMuted: boolean` (при `true` — полное отключение всего звука по аналогии с `musicMuted` / `soundMuted`).

**Почему:** Совпадает с формулировкой «как у Музыка и Звуки» и не смешивает общий масштаб с пер-канальными ползунками.

**Альтернатива:** только `masterVolume` без mute — отклонена: пользователь явно просил то же поведение интерфейса, включая чекбокс включения ветки.

### 2. Формула эффективного gain

**Выбор:** эффективная громкость музыки = `masterVolume * (masterMuted ? 0 : 1) * musicVolume * (musicMuted ? 0 : 1)`; звуков — `masterVolume * (masterMuted ? 0 : 1) * soundVolume * (soundMuted ? 0 : 1)`. Константа α и `setQuietMusicForScreenReader` удаляются.

**Почему:** Один понятный «рычаг» для всего выхода; пер-канальные значения остаются номиналами при выключенном общем mute.

**Альтернатива:** отдельный узел только на музыке — отклонена: «общая громкость» должна влиять на обе ветки.

### 3. Граф Web Audio

**Выбор:** ввести общий выходной `GainNode` (`_masterOutputGain` или эквивалент), к которому подключаются `_masterMusicGain` и `_masterSoundGain`, затем `destination`; параметр `masterVolume` / `masterMuted` управляет только этим узлом. Пер-канальные узлы продолжают отражать только `musicVolume`/`soundVolume` и их mute.

**Почему:** Явное разделение «канальный номинал» vs «общий множитель», проще сопровождать и тестировать по узлам.

**Альтернатива:** перемножать всё в одном gain на канал — допустима, но хуже отражает спецификацию «номинал ползунков при mute ветки».

### 4. Умолчания и совместимость сохранений

**Выбор:** `engineDefaults.masterVolume === 1.0`, `masterMuted === false`. При `loadSettings` ключ `quietMusicForScreenReader` из старого JSON игнорируется (не попадает в результат типа `Settings`); при следующем `saveSettings` ключ не записывается.

**Почему:** Поведение для большинства пользователей совпадает с прежним при выключенной «тихой музыке» и полном master.

**Риск:** у кого был включён quiet mode — после обновления услышат более громкую музыку при тех же ползунках; это осознанная смена продукта.

### 5. UI и i18n

**Выбор:** новые ключи `u()` для подписи секции «Громкость» и для чекбокса включения общего звука; для ползунка общей громкости — тот же механизм процентов/`aria-valuetext`, что у музыки и звуков (расширение существующего требования i18n при необходимости).

## Risks / Trade-offs

- **[Breaking]** Публичный тип `Settings` и экспорт настроек меняются → авторы игр должны пересобрать при обращении к полям. **Митигация:** удалить поле из типа; документировать в proposal/tasks.

- **Потеря дакинга только музыки под скринридер** → общая громкость грубее. **Митигация:** зафиксировать как non-goal; пользователь может снизить музыку отдельным ползунком.

- **Дублирование разметки трёх строк громкости** → чуть больше кода. **Митигация:** при реализации вынести общую сборку строки (рефактор по желанию в задаче).

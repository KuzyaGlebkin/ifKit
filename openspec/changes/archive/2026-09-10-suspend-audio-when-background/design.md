## Context

single HTML-сборка и веб-движок используют Web Audio API (`audio.ts`): ленивый `AudioContext`, музыка через buffer sources и мастер-гейны, пользовательские `masterVolume`/mute уже отделены от остановки музыки в меню (отдельное требование в спецификации). Сейчас нет подписки на видимость документа, поэтому при уходе вкладки/приложения на задний план воспроизведение продолжается.

## Goals / Non-Goals

**Goals:**

- При `document.visibilityState === 'hidden'` (или эквивалентный переход через `visibilitychange`) полностью прекратить слышимый вывод музыки и звуков без изменения сохранённых настроек громкости и mute.
- При возврате `visible` восстановить нормальную работу движка: если контекст был приостановлен для фона — возобновить так, чтобы сцена и намерения музыки вели себя предсказуемо (как после политики autoplay/`resume`).
- Одна точка регистрации (при инициализации аудио или при создании `AudioContext`), без дублирования логики по модулям.

**Non-Goals:**

- Отдельная пользовательская настройка «играть в фоне».
- Гарантии для произвольных нативных обёрток без проверки: Tauri/WebView — проверить отдельно; если события видимости не приходят, зафиксировать в Open Questions и при необходимости добавить follow-up.

## Decisions

1. **Использовать Page Visibility API** (`document.addEventListener('visibilitychange', …)`), опираться на `document.visibilityState`. Это стандартно для вкладок и большинства webview; покрывает переключение приложения на мобильных в типичном случае.

2. **При hidden вызывать `AudioContext.suspend()`**, при `visible` — `resume()`, если контекст уже создан. Это заглушает весь выход движка, останавливает обработку графа и не требует временно менять `_masterOutputGain`/канальные номиналы (которые отражают настройки пользователя). Альтернатива «gain в 0» оставляет граф активным и легче рассинхронизировать с сохранёнными номиналами; suspend семантически ближе к «приложение не на переднем плане».

3. **Не записывать в user settings** флаг фоновой паузы: это временное состояние рантайма, аналогично системной паузе, а не mute из UI.

4. **Если контекста ещё нет** — обработчик visibility может быть лёгким no-op или не регистрироваться до первой инициализации (предпочтительнее регистрировать один раз при создании контекста, чтобы не усложнять порядок init).

## Risks / Trade-offs

| Риск | Смягчение |
|------|-----------|
| Некоторые WebView могут реже или иначе диспатчить `visibilitychange` | После интеграции проверить Tauri; при расхождениях — отдельная задача (например `blur`/`focus` window, если доступно из оболочки). |
| `suspend()` во время звука обрывает слышимость, но one-shot звук при коротком «мигании» вкладки | Приемлемо для цели «не мешать другому приложению»; отдельный debounce не вводить в первой итерации. |
| Двойной `resume()` с уже существующими one-shot обработчиками клика | Текущий auto-resume на первый жест сохраняем; дополнительный `resume()` при visible безоперен для большинства браузеров. |

## Migration Plan

Изменение только в рантайме движка; откат — удаление слушателя и вызовов suspend/resume. Сохранения и API игр не трогаются.

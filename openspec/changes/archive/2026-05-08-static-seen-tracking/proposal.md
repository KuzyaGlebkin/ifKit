## Why

Подсветка «непросмотренных» блоков считается **отдельно для каждого ключа сцены**. Статический UI (`static` в `defineGame`, зона `before` / слоты) повторяется на всех сценах и отражает **общее** состояние игры. Когда значение меняется в одной сцене, хеш текста попадает в seen только для этой сцены; при переходе на другую сцену тот же HTML считается «новым» для её ключа и ошибочно подсвечивается. Нужно развести учёт seen для **тела сцены** и для **статического слоя**.

## What Changes

- Ввести отдельное хранилище (или отдельный ключ/namespace в существующем JSON) для хешей **статического** контента, **не** привязанного к `sceneKey`.
- При маркировке «unseen» различать дочерние узлы, относящиеся к статическому слою, и узлы чистого контента сцены: для первых использовать глобальный учёт, для вторых — текущее поведение по `sceneKey`.
- Сохранить связку с настройкой «подсветка непросмотренного» и с `resetSeenContent` (сброс обоих учётов). Осознанную **миграцию** старых значений в `localStorage` для seen **не делать**: при необходимости игрок воспользуется уже существующей кнопкой сброса просмотренного.
- Покрыть поведение сценариями в спецификации `seen-content` (и при необходимости уточнить взаимосвязь со `static-scene-zones`).

## Capabilities

### New Capabilities

(none — поведение расширяет существующую модель seen/unseen)

### Modified Capabilities

- `seen-content`: требования к `initSeenContent`, `markAndHighlight`, `resetSeenContent` — раздельный учёт seen для статического слоя и для контента сцены; сценарий «смена только глобального state в сцене A → переход в сцену B без ложной подсветки статического блока при неизменном HTML».
- `static-scene-zones`: краткое уточнение (если нужно для контракта), что узлы из зон `static` участвуют в глобальном seen для подсветки, а не только в per-scene.

## Impact

- `src/ifKit/seen-content.ts` (основная логика и формат записи под ключом `ifkit:seen`; без сохранения старого формата хешей между версиями движка).
- `src/ifKit/scenes.ts` — точка вызова `markAndHighlight` / способ передать границы «static vs scene» (например, счётчик детей, data-атрибуты, или отдельный вызов).
- `src/ifKit/renderer.ts` или конвейер compose — если потребуется маркировать границу static/scene в HTML.
- Возможные правки тестов/типов; демо-игра `src/game.ts` без обязательных изменений API для автора.

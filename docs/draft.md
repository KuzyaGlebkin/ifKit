# Как работает проект ifKit

## Общая схема сборки и запуска

1. **npm** – менеджер пакетов. Все зависимости и скрипты описаны в [`package.json`](package.json).
   - Скрипт `dev` запускает Vite в режиме разработки.
   - Скрипт `build` выполняет извлечение переводов, компиляцию TypeScript и сборку через Vite.
   - Есть дополнительные скрипты для Tauri (Desktop/Mobile) и извлечения i18n.

2. **Vite** – современный сборщик для браузерных приложений. Его конфигурация находится в [`vite.config.ts`](vite.config.ts).
   - `root: 'src'` указывает, что корень клиентского кода – папка `src`.
   - Плагин `vite-plugin-singlefile` объединяет вывод в один HTML‑файл.
   - Пользовательский плагин `ifkit-rename-web-html` после сборки переименовывает `index.html` в `${name}_${version}.html` (например, `ifkit_0.1.0.html`).
   - В разделе `build` указано:
     - `outDir: '../dist'` – готовые файлы помещаются в папку `dist` относительно корня репозитория.
     - `minify: false`, `target: 'esnext'` и другие настройки оптимизации.
   - В `resolve.alias` добавлен алиас `@ifkit-storage` → `src/ifKit/storage/local.ts`.

3. **HTML‑точка входа** – [`src/index.html`](src/index.html).
   - Подключает общий стиль `<link rel="stylesheet" href="/style.css" />`.
   - В конце тела подгружает TypeScript‑модуль:
     ```html
     <script type="module" src="/game.ts"></script>
     ```
   - При разработке Viteserves этот файл из `src/game.ts`; после сборки он берется из сгенерированного бандла.

4. **Основной TypeScript‑модуль** – [`src/game.ts`](src/game.ts).
   - Импортирует иконку фавиконка (через Vite asset URL) и добавляет её в `<head>`.
   - Импортирует функцию `defineGame` и типы из локального пакета `ifKit` (это код движка, расположенный в `src/ifKit`).
   - Импортирует описания сцен (`scenes.ts`), начальное состояние (`state.ts`) и переводы (`locales/`).
   - Вызывает `defineGame({...})`, передавая:
     - `sourceLanguage: 'ru'`.
     - Метаданные игры (title, description).
     - `initialState` – объект состояния.
     - `watch` – реактивные подписки на изменение полей состояния (вывод snackbar‑ов).
     - `static` – функция, выводящая статическую панель (HP и золото) перед каждой сценой.
     - `scenes` – объект со всеми сценами игры.
     - `locales` – переводы для английского и русского языков.

5. **Описание состояния** – [`src/state.ts`](src/state.ts).
   - Экспортирует тип `GameState` и объект `initialState` со значениями по умолчанию (hp, gold, hasBranch и т.д.).

6. **Сцены** – [`src/scenes.ts`](src/scenes.ts).
   - Содержит карту сцен, где каждая сцена определяет:
     - Текст (с использованием функции `t` для локализации).
     - Возможные действия (`act`) и переходы (`goto`).
     - Возможные побочные эффекты (изменение состояния).

7. **Локализация** – папка [`src/locales/`](src/locales/).
   - Файлы вида `en.ui.json`, `en.game.json`, `ru.ui.ts`, `ru.game.ts`.
   - Разделяют интерфейс (UI) и игровой текст (game), что позволяет переключать язык в runtime.

8. **Стили** – [`src/style.css`](src/style.css).
   - Общий CSS для всей игры, включает оформление controls, контента, анимаций и т.д.

9. **Сборка для Tauri** (опционально) – конфигурация [`vite.config.tauri.ts`](vite.config.tauri.ts).
   - Похожа на обычную Vite‑конфигурацию, но используется при создании Desktop/Mobile приложений через Tauri.
   - Скрипты `tauri:dev`, `tauri:build` и т.п. в `package.json`.

## Как выглядит процесс разработки

```bash
# Установить зависимости
npm install

# Запустить dev‑сервер (горячая перезагрузка)
npm run dev

# Сборка для веба
npm run build

# Сборка для Tauri (Desktop)
npm run tauri:dev   # разработка
npm run tauri:build # produkcija
```

После сборки в папке `dist` появляется файл `ifkit_0.1.0.html` (и сопутствующие ассеты), который можно открыть в любом браузера или упаковать в Tauri‑приложение.

## Внутренняя структура движка (`src/ifKit/`)

Папка `src/` содержит подпапку `ifKit/` – это собственно движок, который используется в `game.ts` через импорт `{ defineGame, H2, P, t } from './ifKit'` (посредством `index.ts`). Основные файлы:

- `index.ts` – экспортирует публичный API движка: `defineGame`, хелперы тегов (`H2`, `P`, `t` и т.д.), типы и утилиты.
- `engine.ts` – ядро движка: обработка вызовов `defineGame`, управление состоянием, рендеринг, обработка актов/голоса, подписки `watch`.
- `renderer.ts` – отвечает за вставку элементов в DOM, создание и обновление узлов на основе теговых функций.
- `scenes.ts` (внутри ifKit) – содержит типы и утилиты для работы со сценами (например, `defineScene`, `act`, `goto`). Не путать с проектным `src/scenes.ts`.
- `i18n.ts` – функции локализации, загрузка переводов, хелпер `t`.
- `state.ts` – типы и утилиты для работы с состоянием игры (глубокие копии, слияния).
- `tag-functions.ts` – реализация теговых шаблонов, которые позволяют писать `H2`\`Заголовок\`` и т.п., создавая виртуальные узлы.
- `builtin-ui.ts` – базовые UI‑компоненты (кнопки, диалоги, панель контролов) используемые движком по‑умолчанию.
- `audio.ts` – простейшая обёртка над HTML5 Audio для фоновой музыки и эффектов.
- `saves.ts` и `saves-modal.ts` – логика сохранения/загрузки игр и модальное окно управления сохранениями.
- `settings.ts` и `settings-modal.ts` – управление настройками (язык, громкость и т.д.) и их модальное представление.
- `snackbar.ts` – лёгкая система уведомлений, используемая в `watch`.
- `modal-focus-lock.ts` – утилита для ловли фокуса внутри модальных окон (доступность).
- `lucide-icons.ts` – подключение набора иконок Lucide.
- `seen-content.ts` – отслеживание уже просмотренного контента (для подсказок «новое»).
- `session-main-menu.ts` – главное меню сессии (загрузка, настройки и т.д.).
- `ui-keys.ts` – обработка горячих клавиш UI.
- `chrome-i18n.ts` – stub для совместимости с расширениями Chrome (если понадобится).
- `locale-templates.ts` – шаблоны для генерации файлов переводов.
- `storage/` – абстракция над локальным хранилищем (`local.ts` – реальная реализация через `localStorage`; алиас `@ifkit-storage` ведёт именно сюда).
- `layout.ts` – **пустой модуль‑заглушка** (экспортирует пустой объект). Ранее здесь находились хелперы фокуса и доступности, но они были удалены в коммите *remove‑screen‑reader*; файл оставлен, чтобы не ломать импорты.

Все эти модули совместно образуют движок, который в `game.ts` подключает сцены, состояние и локализацию проекта, после чего `defineGame` запускает главный цикл: рендерит статическую панель, показывает текущую сцену, обрабатывает действия (`act`) и переходы (`goto`), реагирует на изменения состояния через `watch` и обновляет интерфейс.
